# ADR-0005: ISO 20022 as the payments vocabulary

**Status:** accepted

## Decision
- Every transfer carries an `EndToEndId` and a `UETR` (UUID v4) from creation.
- Failure reasons use ISO 20022 `ExternalStatusReason1Code` values end to end (`AM04` insufficient funds, `AC01`
  bad account, `AC04` closed, `AC06` blocked, `AM02` limit, `FRAD` fraud, `DUPL` duplicate). The same code appears
  in REST problem details, pain.002 reports, Kafka events and the UI.
- Supported messages: pain.001.001.09 in; pain.002.001.10, pacs.008.001.08 and camt.053.001.08 out.
  See [iso20022.md](../iso20022.md).
- Parsing matches elements by local name, so any pain.001.001.xx version is accepted. Group-header integrity
  (NbOfTxs, CtrlSum, unique EndToEndIds) is enforced. Hardened XML parser (no DTDs or external entities), with a
  2 MB / 500-transaction limit.

## Consequences
Integrating with a clearing house or a corporate ERP is a mapping exercise, not a redesign. Full XSD validation
against the official schemas is deferred: the structural checks cover what the bank acts on.
